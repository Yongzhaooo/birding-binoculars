# 望远镜数据库架构

本项目从已核验的个人参数表生成公开目录，在VPS上提供查询、实拍投稿和人工审核。它与留学案例库采用相同的Python、SQLite、Caddy、systemd部署方式，不复用留学业务数据或凭据。

## 数据和组件

- `data/catalog.json` 是92款初始公开参数和参考入手价格的版本化来源。原Excel首页、评分推荐、交易平台商品、卖家、账号和抓取响应不进入公开仓库。
- `telescope/storage.py` 管理SQLite。初始型号、投稿、审核记录和字段覆盖分开保存。升级代码重新导入初始目录时不会覆盖已审核的用户补充。
- `telescope/server.py` 提供公开查询和投稿。投稿先待审，图片经过解码、尺寸限制和重新编码，不保留原文件的EXIF定位信息。未批准的图片和资料不会进入公开接口。
- `telescope/static/` 是无构建步骤的浏览器界面。筛选、型号详情、实拍画廊和投稿使用同一接口，文本通过DOM文本节点显示。
- 审核通过SSH运行命令行工具，不开放公网管理接口。审核员可查看完整投稿、预览待审图片并单条批准或拒绝。已批准参数保留来源和说明。
- 程序在`/opt/telescope-db/releases/<commit>`，可变数据库和图片在`/var/lib/telescope-db`，系统用户独立。Caddy为`wyj.cangming.fyi`终止TLS，只转发到回环端口8092。

## 取舍

单机SQLite适合这个个人目录。只增加图片处理所需的Pillow，不引入前端框架、账号系统或独立对象存储。匿名投稿限量接收，人工批准后公开。图片版权归上传者，上传者授权本站展示，不自动改授GPL。

## 实施与恢复

1. 生成并检查公开数据与单页Excel，确认不含推荐首页及交易明细。
2. 实现目录和待审投稿，使用合成图片验证解码、隐私及审核边界。
3. 发布GPL源码到GitHub，部署独立服务与Caddy站点，检查现有留学服务仍可访问。
4. 数据库与图片随同备份。代码回退只切换`current`，不覆盖运行数据。升级拒绝未知数据库版本。

本轮脚本、预览、测试数据库和部署包由当前会话负责，保存在现有`.runtime/`内。上线后保留必要的重建及验收证据，下次发版复查，不自动删除。公开代码与数据通过根目录Git白名单发布，原始研究资料留在本地。
